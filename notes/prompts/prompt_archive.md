本文件记录实验中实际使用的全部关键提示词，用于可复现与 AI 使用披露。

## P1 系统提示（所有生成任务共用）

```
你是一名资深中文游戏叙事设计师，擅长为角色扮演游戏撰写性格鲜明的 NPC 对话。
你只写角色真正说出口的话，绝不写动作、神态、旁白或括号说明。
你输出的一切内容必须是可直接被程序解析的 JSON，不写解释、不加 Markdown 代码块。
```

## P1b 对话策略库（tactic planning，2026-11-09 加入）

系统在扩写前先由确定性规划器 `plan_tactic(level, depth, player_intent, key)` 决定本句的
对话行为，再把策略名与一句释义注入提示。规划规则：

- 第 1 层固定 `戒备`；
- 第 `d-1` 层及以后（接近叶层）在 `揭示 / 收尾 / 松动` 中按节点 id 的 CRC32 哈希选择；
- 中间层按玩家选项意图映射：追问→回避/松动、共情→松动/揭示、施压→强硬/回避、
  威胁→强硬/收尾、交易→交易/试探、转移→收尾/回避；未识别意图时在 `试探/回避/松动` 中选。

```
戒备：用短句设防，先确认对方来历，绝不先透露自己的事
试探：抛一句带钩子的话，试探对方是否可信，暗示自己知道些内情
回避：把话题挡回去，用一件具体物件或一个借口转移
松动：态度松动一点，透露一条与自己目标相关的小线索
揭示：说出不愿说的往事的一部分，但故意不说完
交易：明确提出一个可以立刻兑现的交换条件
强硬：被逼到墙角，用冷话或威胁顶回去
收尾：结束这段交谈，留下一个未解的悬念
```

设计动机：基线模型在长 prompt 下容易"所有分支说同一种话"。把"说什么类型的话"
从生成任务里剥离出来，模型只负责"怎么把这句话说好"，可在不增加模型容量的前提下
提升分支间的行为差异。

## P3 逐节点扩写（主实验，levelwise，chunk_size=1）

> 2026-11-09 修订：默认改为**一次只扩写一个节点**。实测多节点同批生成时 1.5B 会把
> 不同节点的历史与台词混在一起（NPC 说出玩家的台词），逐节点生成后重复句率降为 0。

```
【输出示例】
节点 x1 的策略：试探
输入：{"id":"x1","depth":2,"history":"（玩家刚走近）｜ NPC：这儿的规矩是先报名字。｜ 玩家：我叫阿禾。"}
输出：{"nodes":[{"id":"x1","line":"阿禾。名字不坏。你要打听的事，值不值得我开口？","emotion":"试探","options":["我知道你缺人手。","我只想知道那天晚上的事。"]}]}

【已出现过的台词（不要重复或改写它们）】
- {最近 12 条台词}

【本次任务】当前是第 {level} 层。为下面每个节点续写 NPC 的下一句台词
（注意：玩家台词只是上下文，你只能写 NPC 的话）：
节点 n5（第 3 层）｜本句策略：回避（把话题挡回去，用一件具体物件或一个借口转移）
    （玩家刚走近，还没开口）
    NPC：……
    玩家：……

【硬性要求】
1. 台词 20-45 个汉字，口语化，符合上面的说话方式；每句必须落到一个具体细节
   （物件、地点、时间、数字或往事），不要空泛表态；
2. 严格实现该节点标注的【本句策略】，但不要把策略名称写进台词；
   {非叶层：每个节点写一句 NPC 台词，并给出恰好 2 个玩家可选回应；两个选项意图必须明显不同……}
3. 只写 NPC 说出口的话：禁止括号、禁止动作/神态/心理描写、禁止"（沉默）"这类提示；
4. 台词必须接住玩家最后那句话，且不得与已出现台词相同或近似；禁止通用空话；
5. 选项不超过 20 个汉字，必须是玩家会说的话；
6. NPC 有自己的目的：不要反客为主采访玩家，不要连续提问；
7. 不得与本 NPC 的设定、禁忌、世界观冲突；不得出现"AI""模型""对话树"等元词。

【输出格式】只输出一个 JSON 对象：
{"nodes":[{"id":"节点id","line":"台词","emotion":"情绪词","options":["选项1","选项2"]}]}
```

叶层变体：`这是对话的最后一层（第 {d} 层），每个节点只写一句收尾台词，options 必须为空数组 []。`

## P4 一次性整树生成（oneshot 消融）

```
【任务】生成一棵完整的 NPC 对话树：根节点为第 1 层，共 {d} 层，每个非叶节点恰好 2 个玩家选项，
总节点数必须为 {2^d-1}。节点 id 从 n1 开始按层序编号……
```

## P5 JSON 修复重试（解析失败时触发，最多 1 次）

```
上一条输出无法被 JSON 解析，错误信息：{err}
请把它改写成严格合法的 JSON，只输出形如 {"nodes":[...]} 的对象，不要解释，不要代码块。
```

## P6 LLM-as-judge 评审

```
【世界观】…【NPC 设定】…
【待评对话树】
[L1] NPC（情绪）：…
  └ 选项1：…
      [L2] NPC（情绪）：…
【评分说明】每项 1-5 分（整数），5 分最好。
1. consistency：台词与世界观、NPC 设定是否矛盾；不同分支之间是否自相矛盾。
2. persona_stability：是否从头到尾保持同一个人格与说话方式；深层节点是否退化为通用口吻。
3. choice_meaningfulness：同一节点两个选项是否代表真正不同的立场或后果。
【输出】{"consistency":4,"persona_stability":4,"choice_meaningfulness":3,"reason":"不超过 60 字"}
```

评审参数：固定 base 模型、温度 0.3、每棵树 3 次独立采样取均值、**不告知深度与方法（盲评）**。

## P7 训练语料合成（非人写，程序化）

- 词槽：`{place}` 取世界观名，`{w0}{w1}thing` 取该世界 `tone_words`；
- 台词类别由同一个 `plan_tactic()` 先决定（与实验阶段一致），再从对应类别
  （戒备/试探/回避/松动/揭示/交易/强硬/收尾）的模板中抽取；
- 选项按六种意图（追问/共情/施压/交易/威胁/转移）抽两种，保证意图互斥；
- 输入提示与实际推理时 `build_expand_messages()` 完全一致，保证训练-推理同分布。
